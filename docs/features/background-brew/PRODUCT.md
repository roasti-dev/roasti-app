# Фоновое заваривание + раздел «Мои заваривания» — продуктово-дизайнерская спека

Статус: draft / согласование
Платформа: Android (iOS позже)
Эпик: фоновые длинные шаги + персистентные заваривания + история

---

## 1. Проблема и цель

Сейчас заваривание в приложении — эфемерный процесс: пользователь идёт по шагам
рецепта с таймером, экран должен быть включён, состояние живёт только в памяти и
исчезает при выходе из экрана/приложения.

Это ломается на рецептах с **длинным ожиданием**. Канонический кейс — **колд брю**:
смесь должна настаиваться **1–4 дня**. Держать приложение открытым всё это время
невозможно.

**Цель фичи:**

1. Пользователь может «отпустить» длинный шаг в фон и получить **локальное
   уведомление**, когда шаг завершится.
2. Запущенное заваривание **не теряется** при закрытии приложения, перезапуске
   телефона и т.п. — оно всегда доступно как активное.
3. Появляется понятное место для **активных** и **завершённых** завариваний.

---

## 2. Ключевая сущность: Brew

Вводим новую первоклассную сущность — **Brew** (заваривание).

- **Recipe** — шаблон («как варить»). Не меняется.
- **Brew** — конкретный запуск рецепта во времени, со своим состоянием и прогрессом.

Один рецепт можно заварить много раз → много Brew'ов. Brew ссылается на рецепт,
но хранит собственную копию шагов на момент старта (рецепт могут потом
отредактировать/удалить — запущенное заваривание не должно сломаться).

### Состояния Brew

| Статус       | Что значит                                                        |
|--------------|-------------------------------------------------------------------|
| `brewing`    | Пользователь активно идёт по шагам (foreground-таймеры)            |
| `waiting`    | Длинный шаг отпущен в фон, ждём срабатывания будильника            |
| `completed`  | Все шаги пройдены, заваривание уехало в Историю                    |
| `cancelled`  | Пользователь отменил заваривание                                   |

Переходы:

```
старт рецепта ──> brewing
brewing ──(кнопка "Уведомить когда готово" на длинном шаге)──> waiting
waiting ──(будильник сработал / юзер нажал "Готово, продолжить")──> brewing
brewing ──(пройден последний шаг)──> completed
brewing | waiting ──(отмена)──> cancelled
```

## 3. Персистентность (требование «ничего не теряется»)

**Brew сохраняется с момента старта рецепта**, а не только при уходе в фон.

Любое заваривание — короткий V60 или многодневный колд брю — с первого шага
попадает в хранилище и в раздел активных. Закрытие приложения, сворачивание,
перезапуск телефона — Brew остаётся активным и пользователь его находит.

Это сознательно расширяет скоуп относительно «сохраняем только фоновые»: цель —
надёжность, заваривание никогда не пропадает молча.

## 4. Фоновый шаг

### 4.1 Когда доступна кнопка

Кнопка **«Уведомить когда готово»** (рабочее название) появляется **только на
шагах с ожиданием > 5 минут** (`durationSeconds > 300`).

Короткие prep-шаги (налить 50 мл, размешать 30 сек) работают как сейчас —
обычный foreground-таймер, без кнопки. Уведомление на 30 секунд не имеет смысла.

### 4.2 Выбор времени (диапазонные шаги)

Длительность длинного шага задаёт пользователь через **picker времени** —
**переиспользуем тот же компонент, что в редактировании шага рецепта**.

- Picker **предзаполнен** значением из параметра шага (например 48 ч).
- Пользователь может оставить дефолт или выбрать другое (24 / 72 / 96 ч и т.д.).

Так покрывается «1–4 дня»: автор рецепта кладёт рекомендованное значение,
заваривающий подстраивает под себя.

### 4.3 Что происходит после подтверждения

1. Brew → `waiting`, фиксируется `waitUntil = now + выбранная длительность`.
2. Планируется **локальный будильник на ОС** на `waitUntil` (переживает закрытие
   приложения и перезагрузку телефона).
3. Пользователь свободен — может закрыть приложение.
4. Brew виден в карусели активных с обратным отсчётом («осталось 18 ч»).

## 5. Уведомление

- Локальное (на устройстве), без сервера.
- **Отправляется ровно в момент завершения шага** (срабатывание будильника).
- Содержит название рецепта/шага: «Cold Brew готов — настаивание завершено».
- **Действие — голый тап** (v1): открывает запущенное заваривание **на следующем
  шаге**. Brew → `brewing`.
- Кнопки в уведомлении («+30 мин», «Готово») — **вне v1**, во вторую итерацию.
  Аналоги этих действий доступны на экране самого Brew.

### Разрешения

- Android 13+: рантайм-разрешение на уведомления (`POST_NOTIFICATIONS`).
  Запрашиваем при первом уходе шага в фон, с понятным объяснением зачем.
- Точность будильника — см. техническую спеку. Продуктово: для ожидания в
  часы/дни допустима погрешность в минуты.

### Принцип: wall-clock = источник правды, уведомление = best-effort

Готовность фонового шага определяется **сравнением системного времени с
`waitUntil`**, а НЕ фактом доставки уведомления.

Уведомление — лишь best-effort пинок от ОС. Если система не разбудила
(Doze / OEM убил процесс / телефон был выключен в момент `waitUntil`) — это не
теряет состояние: при следующем открытии приложения мы сами видим, что
`waitUntil` прошёл, и показываем шаг завершённым («Готово, продолжить»).
Никаких «возможно готово, проверьте» — мы знаем точно.

## 6. Навигация и размещение

### 6.1 Активные — секция в списке Recipes

Активные заваривания живут **инлайн-секцией сверху на экране Recipes** (НЕ
отдельный таб, bottom bar не меняется).

Секция **«Сейчас завариваются»** — горизонтальная карусель (свайп вбок), чтобы
несколько параллельных Brew'ов не толкали ленту рецептов вниз.

```
Recipes:
┌─ Сейчас завариваются ───────────────────────  [История →]
│ ┌──────────┐ ┌──────────┐ ┌──────────┐
│ │Cold Brew │ │Cold Brew │ │   V60    │   ← карусель, свайп
│ │ ⏳ 18h   │ │ ⏳ 40h   │ │ ▶ 3/5    │
│ └──────────┘ └──────────┘ └──────────┘
└───────────────────────────────────────────────
  Рецепты
  [обычная лента / грид рецептов]
```

- Секция показывается только если есть активные Brew'ы (`brewing` + `waiting`).
- Карточка Brew ≠ карточка Recipe: показывает прогресс/таймер, а не лайки.
  - `waiting`: обратный отсчёт «осталось 18 ч».
  - `brewing`: прогресс «шаг 3/5» + кнопка продолжить.
- Тап по карточке → открыть Brew в нужной точке (экран ожидания или шаги).

Бейдж со счётчиком активных завариваний — на табе Recipes в bottom bar
(число `brewing` + `waiting`).

### 6.2 Параллельные заваривания

Поддерживается несколько активных Brew'ов одновременно, **без лимита** (например
два колд брю на разных зёрнах + V60). Каждый — отдельная карточка в карусели, у
каждого свой будильник/прогресс.

### 6.3 Завершённые — отдельный экран «История/Журнал»

Ссылка «История →» из шапки секции активных → полноэкранный список завершённых
завариваний (дневник). Растёт без лимита, не засоряет Recipes.

Каждая запись: рецепт, дата, опциональная заметка.

## 7. Действия над активным Brew

| Действие                | Где                              | Поведение                                          |
|-------------------------|----------------------------------|----------------------------------------------------|
| Продолжить              | карточка / экран ожидания        | переход к следующему/текущему шагу                 |
| Готово, продолжить      | экран ожидания (`waiting`)       | прервать ожидание досрочно, отменить будильник, дальше |
| Отменить заваривание    | карточка (свайп) / экран Brew    | Brew → `cancelled`, отменить будильник, убрать из карусели |

Досрочное «Готово» нужно: колд брю готов раньше — пользователь снимает сейчас, не
дожидаясь будильника.

---

## 8. Финал заваривания

После прохождения последнего шага:

1. Экран завершения: «Заваривание готово».
2. **Опционально** — поле заметки (как прошло, вкус). Не обязательно, можно
   пропустить.
3. Brew → `completed`, уезжает в Историю.

Оценка/рейтинг звёздами на финале — **вне v1** (возможна отдельная итерация).
В v1 только опциональная текстовая заметка.

## 9. Состояния экранов (UX)

| Сценарий                                  | Поведение                                            |
|-------------------------------------------|------------------------------------------------------|
| Нет активных Brew'ов                      | секция «Сейчас завариваются» скрыта                  |
| Brew `waiting`, приложение открыли раньше | экран ожидания с обратным отсчётом + «Готово, продолжить» |
| Будильник сработал, приложение закрыто    | локальное уведомление                                |
| Будильник сработал, приложение открыто    | Brew в карусели → состояние «шаг завершён, продолжить» |
| Будильник НЕ сработал (Doze/OEM/выключен) | при открытии: `waitUntil` прошёл → «Готово, продолжить» (wall-clock-правда) |
| История пуста                             | empty-state «Здесь появятся завершённые заваривания» |

## 10. Что НЕ входит в v1 (явно отложено)

- Кнопки-действия внутри уведомления («+30 мин», «Готово»).
- Оценка звёздами на финале (только текстовая заметка).
- Шаринг завершённого заваривания в ленту/соцчасть.
- Изменение времени уже запущенного фонового шага.
- iOS-реализация.

---

## 11. Решённые вопросы

1. **Лимит параллельных Brew'ов** — без лимита.
2. **Будильник не сработал (Doze/OEM/выключенный телефон)** — статус считаем по
   wall-clock (см. §5 «wall-clock = источник правды»). При открытии приложения
   показываем актуальное состояние: если `waitUntil` прошёл — шаг завершён,
   «Готово, продолжить». Никаких «возможно готово».
3. **Бейдж активных на табе Recipes** — да, счётчик `brewing` + `waiting` (§6.1).
4. **Локализация (en + ru)** — да, обе локали обязательны; конкретные строки
   собираем на этапе реализации.
